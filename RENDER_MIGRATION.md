# Migrating Aegent from Railway to Render + Neon

Zero cost at pilot scale. Keeps `git push` deploys and the single-origin
SPA+API shape you already have.

## What you'll end up with

| Piece | Where | Cost |
|---|---|---|
| Node server (Express + Socket.io) | Render Free Web Service | $0 |
| Postgres | Neon Free Tier (already yours) | $0 |
| SPA | Same Render service, served from `web/dist` | $0 |
| Keepalive pinger | cron-job.org, hits `/healthz` every 10 min | $0 |
| Domain + SSL | Render auto-SSL on your custom domain | $0 |

Everything stays `$0/month` as long as you're inside the free limits:
Render = 500MB RAM / 100GB egress per month; Neon = 0.5GB storage.

## Step 1 — Dump Railway Postgres → Restore to Neon

### 1a. Get both connection strings handy

- **Railway**: open the Postgres service in Railway → Variables → copy
  `DATABASE_URL` (or the "Postgres Connection URL").
- **Neon**: your Neon dashboard → the Aegent project → Connection
  Details → "Connection string". Looks like
  `postgresql://user:pass@ep-xxx.us-east-2.aws.neon.tech/aegent?sslmode=require`.

### 1b. Dump from Railway

From any machine with `pg_dump` installed (PostgreSQL client tools; on
Windows, install via the Postgres installer or scoop):

```powershell
# Replace with your Railway URL
$RAILWAY_URL = "postgresql://postgres:xxx@containers-us-west-xx.railway.app:1234/railway"

pg_dump "$RAILWAY_URL" `
  --no-owner `
  --no-privileges `
  --format=plain `
  --file=aegent-railway-dump.sql
```

The `--no-owner --no-privileges` flags strip Railway-specific ownership
so the restore into Neon's user namespace is clean.

### 1c. Restore into Neon

```powershell
# Replace with your Neon URL
$NEON_URL = "postgresql://user:pass@ep-xxx.us-east-2.aws.neon.tech/aegent?sslmode=require"

psql "$NEON_URL" -f aegent-railway-dump.sql
```

Verify a row made it over:

```powershell
psql "$NEON_URL" -c "SELECT COUNT(*) FROM users;"
psql "$NEON_URL" -c "SELECT COUNT(*) FROM messages;"
```

The counts should match Railway. If `pg_dump` or `psql` complain about
a version mismatch, add `--no-sync` or install the Postgres 16 client
(Neon runs 16).

## Step 2 — Deploy to Render

### 2a. Push the render.yaml

`render.yaml` is already committed at the repo root. Push it:

```bash
git add render.yaml RENDER_MIGRATION.md
git commit -m "Add Render blueprint + migration guide"
git push origin main
```

### 2b. Create the service

1. Sign in at **render.com** (free account, GitHub login works).
2. **New → Blueprint**.
3. Connect your GitHub, pick the `Aegent` repo, branch `main`.
4. Render reads `render.yaml` and shows the plan. Click **Apply**.

### 2c. Fill in the env vars Render asked for

In the service dashboard → Environment:

- `DATABASE_URL` → paste your Neon connection string
- `GROQ_API_KEY` → paste your Groq key (optional: `GROQ_MODEL`, default `openai/gpt-oss-120b`)

(`JWT_SECRET` was auto-generated by Render; `NODE_ENV` was set in the
yaml. Don't touch those.)

Click **Save, Rebuild**. First build takes ~5–8 min (Docker from
scratch); subsequent builds reuse layer cache and run in ~2 min.

### 2d. Confirm it's up

Once the deploy says "Live":

```bash
curl https://aegent-xxxx.onrender.com/healthz
# → {"ok":true,"ts":...,"llm":true,"db":"pg"}
```

If `db` says `"sqlite"` instead of `"pg"`, your `DATABASE_URL` wasn't
set — fix it in Environment and redeploy.

## Step 3 — Set up the keepalive pinger (defeats the 15-min spin-down)

1. Sign up at **cron-job.org** (free, no credit card).
2. **Create cronjob**:
   - **Title**: `Aegent keepalive`
   - **URL**: `https://aegent-xxxx.onrender.com/healthz` (your Render URL)
   - **Schedule**: Every 10 minutes
   - **Request method**: GET
   - **Notifications**: email on failure (optional)
3. Save. First ping fires immediately.

After a day, open the job's history — all green 200 responses means
your Render service is being kept awake 24/7.

### Why 10 minutes

Render spins a free service down after **15 min of silence**. A ping
every 10 min leaves a 5 min safety margin for cron-job.org drift. Any
interval under 14 min works; shorter is wasted invocations against
Render's monthly cap (which is plenty generous — 750 hr/mo on free).

## Step 4 — Point your custom domain at Render

(Skip if you're happy with the `aegent-xxxx.onrender.com` URL.)

1. In the Render service → **Settings → Custom Domain → Add Custom
   Domain** → enter `aegent.yourdomain.com` (or the apex).
2. Render shows the DNS records to add. Usually a `CNAME` to
   `aegent-xxxx.onrender.com` for a subdomain, or an `ANAME`/`ALIAS`
   for the apex.
3. Add those at your domain registrar. Render auto-provisions a free
   Let's Encrypt certificate within ~5 min of DNS propagating.
4. The URL in your custom domain is what you use for `VITE_API_URL`.

## Step 5 — Rebuild the APK with the new backend URL

```powershell
cd "C:\Users\DELL\Aegent Messanger\web"
$env:VITE_API_URL = "https://aegent.yourdomain.com"   # or the onrender.com URL
npm run android:sync
cd android
.\gradlew assembleDebug
```

Then uninstall the old Aegent on your phone (so the webview cache is
clean) and install the fresh APK from
`android/app/build/outputs/apk/debug/app-debug.apk`.

---

## Step 6 — Decommission Railway

Only after you've confirmed the Render + Neon version works end-to-end
on your phone AND messages still appear (so you know data landed):

1. In Railway → the Aegent project → Settings → **Delete Project**.
2. Billing stops immediately. Postgres and server go away in minutes.

Keep the `railway.json` file in the repo for a week or two in case you
want to roll back. Delete it later with:

```bash
git rm railway.json
git commit -m "Decommission Railway deploy"
git push
```

## Troubleshooting

### "db: sqlite" in /healthz after deploy
`DATABASE_URL` isn't set, or has a typo. Check Render → Environment.
Note Render requires `sslmode=require` in the Neon URL (it's in the
string Neon gives you by default).

### Build fails with "no space left"
Render free gives 500MB RAM at build time. Try reducing: in the
Dockerfile, our build stage already prunes dev-deps. If it still
fails, swap `node:22-alpine` for `node:22-slim` (bigger image, less
RAM pressure during build).

### WebSockets drop every 5 min on free Render
Shouldn't happen — Render's Feb 2026 change makes WebSocket messages
count as activity. If it does, verify Socket.io is using transport
`websocket` (not falling back to polling) by inspecting the Network
tab in Chrome DevTools against the running app.

### Neon pauses the database overnight
Neon free scales to zero after ~5 min idle. First query after that
takes ~2s to warm. The keepalive pinger hits `/healthz`, which runs
a `livePresence` touch but not a DB query — add one if cold-starts
annoy. Simplest tweak: change `/healthz` in `server/src/index.ts` to
`SELECT 1` on every call. (Optional; the warm-up is only noticeable
on the first message after a long quiet period.)

### Cost sanity check
Monthly total should be exactly $0. If anything bills you:
- Render: free plan has no card requirement. If you added one, remove it.
- Neon: free plan allowance is 0.5GB. Check Usage; if you've exceeded,
  that's the first thing to notice.
- cron-job.org: free forever.
